# OrbiAgents v0.2.0 release candidate

## Release summary

OrbiAgents v0.2.0 evolves the project from an API-driven visual workflow MVP into a local-first, workflow-oriented multi-agent platform. It retains the visual DAG builder, provider APIs, authentication, saved workflows, replay, sharing, and VS Code extension while adding durable agent context, safe local coding runtimes, parallel orchestration, supervisor controls, and a coworking environment driven by real workflow state.

## Highlights

- Persistent per-agent/shared memory and typed mailboxes
- Anthropic, OpenAI, Gemini, Codex CLI, and Claude Code runtime boundaries
- Parallel DAG execution with circuit breakers and cancellation
- Isolated coding worktrees with explicit operator review
- Orbi-Prime supervision and approval-gated workflow proposals
- Replay navigation, bookmarks, sharing, and operator observability
- Planning, focus, collaboration, and lounge zones driven by live/replay agent state
- Reproducible production Docker images and hardened security boundaries

## Upgrade notes

- Run all Prisma migrations before starting the v0.2.0 server. The production server container does this automatically.
- Existing API-provider workflows remain compatible and require no runtime selection changes.
- Local CLI runtimes require explicit `LOCAL_CLI_*` configuration and an allowed Codex or Claude executable.
- Use a strong production `JWT_SECRET`; the server rejects the documented development secret in production.
- Review preserved coding worktrees manually. OrbiAgents does not commit, merge, push, or delete agent changes automatically.

## Acceptance checklist

Automated and credential-free checks are completed during release preparation. Before publishing the tag and GitHub release, perform these credential-backed checks locally:

- [ ] Run one authenticated Anthropic, OpenAI, or Gemini workflow end to end.
- [ ] Confirm live agent states, mailbox delivery, zone movement, results, usage, and replay.
- [ ] Restart the server and confirm memory, mailboxes, replay bookmarks, and workspace records persist.
- [ ] Enable one local CLI runtime and run it against a disposable repository.
- [ ] Confirm the CLI node uses an isolated worktree and preserves dirty work for review.
- [ ] Apply only explicitly selected files to a clean target, then discard the test workspace through the operator controls.
- [ ] Confirm approval waits, cancellation, and bounded failure recovery are visible and safe.
- [ ] Confirm the dashboard and VS Code webview remain usable at the intended screen sizes.

## Publication steps after acceptance

1. Replace `Unreleased` in `CHANGELOG.md` with the publication date.
2. Commit the acceptance result and changelog date.
3. Create annotated tag `v0.2.0` on the accepted `main` commit.
4. Push the tag.
5. Publish the GitHub release using this document as the release notes.

Do not publish the tag or release before the credential-backed acceptance checklist passes.
